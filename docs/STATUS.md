## Future enhancements

### FE-1 — Read Brawl/P+ `.pac` files directly (replace Rukai Data copy/paste)  ⏳ planned
**Why:** Stage 1 and 4 inputs are copied by hand from Rukai Data pages, and some data the site *draws* is
never *printed*, e.g. the ledge-grab box (see P-MOVE-11). Reading the `.pac` files ourselves gets every value
for every subaction in one run.

**What it unlocks:**
- Move scripts for all subactions → stage 4 input files generated automatically (no copy/paste).
- `LedgeGrabEnable`, `EnableLandingLag`, `AllowInterrupts` etc. → converter sets ledge/auto-cancel/IASA directly (P-MOVE-11).
- Character attributes → the PM side of the attribute mapping (P-ATTR-1).
- Hurtboxes → could generate `HB_` capsules (currently "not generated by pipeline").
- Ledge-grab box, ECB → real sizes instead of guesses.

**Approach (in order of preference):**
1. **brawllib_rs** (<https://github.com/rukai/brawllib_rs>, MIT): the Rust library that generates Rukai
   Data. It's read-only, supports a mod folder layered on a Brawl dump (`BrawlMod::new(brawl, Some(mod))`), and
   exposes `HighLevelFighter` (hurtboxes confirmed in its README; other fields to verify). Plan: a small Rust
   CLI that dumps one fighter to JSON, then our Python reads the JSON. Lowest risk, because it's the parser whose
   output we've already been using.
2. **BrawlCrate/BrawlLib** (C#): we already have a BrawlCrate plugin for animations, and BrawlLib parses
   movesets too. It's an option if brawllib_rs falls short, but plugins run inside the BrawlCrate GUI.
3. **Our own Python parser:** most control, most work (PSA/moveset formats are large). Last resort.

**Unknowns to resolve first:**
- [ ] Does brawllib_rs need a **full extracted Brawl filesystem** plus the P+ SD-card folder, or can it
      read a single `FitCaptain*.pac`? (We have `FitCaptain.pac`, `FitCaptain00.pac`, `FitCaptainMotionEtc.pac`
      in `p+falcon/`.) A full dump needs your own Brawl disc extracted.
- [ ] Which `HighLevelFighter` fields exist: scripts, attributes, hit/hurt/ledge-grab boxes, ECB?
- [ ] Rust toolchain on this machine (`rustup`); build time.
- [ ] Output must match what we copy from Rukai today. Verify on a few moves (e.g. SpecialHi, AttackAirB).

**Feasibility:** Likely possible, since Rukai Data proves the data can be extracted this way. The main risk is
the input-file requirement (full Brawl dump vs single `.pac`).
